## LEGENDA DSL I REGUŁY INTERPRETACJI

Bloki `dsl` są normatywnym, czytelnym dla ludzi i agentów zapisem polityki;
nie są samodzielnie wykonywalnym językiem programowania. Deterministyczne
egzekwowanie realizuje walidator i manifest policy-as-code.

```dsl
DOCUMENT <NAME>                 # nazwa kontraktu
VERSION <INTEGER>               # wersja dokumentu DSL
MODE <STRICT|PROCEDURAL>        # sposób interpretacji
ENV_FILE <RELATIVE_PATH> <OPTIONAL|REQUIRED>
VARIABLE <NAME> TYPE <STRING|INTEGER|NUMBER|BOOLEAN|URL|PATH> FROM ENV [REQUIRED|DEFAULT <VALUE>]
SECRET <NAME> TYPE <STRING|INTEGER|NUMBER|BOOLEAN|URL|PATH> FROM ENV REQUIRED REDACT
# <COMMENT>                     # komentarz objaśniający bez skutku normatywnego

RULE <STABLE_ID> [TYPE <TYPE>]  # początek reguły ze stabilnym identyfikatorem
WHEN <CONDITION>                # warunek aktywacji reguły
DO <ACTION>                     # wymagane działanie po aktywacji
DO REQUIRE <CONDITION>          # wymagany warunek lub dowód
DO ALLOW <ACTION>               # jawnie dozwolony wyjątek w podanych granicach
FORBID <ACTION>                 # bezwzględny zakaz po aktywacji
ASSERT <POSTCONDITION>          # warunek, który musi być prawdziwy po wykonaniu
NEXT <STATE> [OR BLOCKED]       # dozwolone przejście maszyny stanów
```

Semantyka:

1. Reguła aktywuje się tylko, gdy jej `WHEN` jest prawdziwe. Wszystkie jej
   linie `DO`, `FORBID`, `ASSERT` i `NEXT` obowiązują łącznie.
2. `TYPE REQUIRED` wymaga działania lub dowodu; `TYPE FORBIDDEN` blokuje
   wskazaną czynność. Brak `TYPE` w procedurze oznacza regułę wymaganą.
3. `AND` oznacza koniunkcję, `OR` alternatywę, `IN [...]` przynależność,
   `=` równość, `!=` nierówność, a `<=` limit włącznie. Nawiasy mają
   pierwszeństwo przed operatorami.
4. Wartości w cudzysłowie są literałami. Nazwy wielkimi literami oraz
   `{PLACEHOLDER}` są symbolami kontraktu i muszą zostać rozwiązane z
   bieżącego źródła prawdy; nie wolno zgadywać ich z nazwy.
5. `NEXT` nie zezwala na pominięcie stanu. Brak wymaganej autoryzacji prowadzi
   do `WAIT_FOR_APPROVAL` lub `BLOCKED`; bezpieczna korekta zakresu wewnątrz
   już zleconego celu aktualizuje plan i może zachować autoryzację wykonania.
6. Konflikty rozstrzyga kolejność źródeł z `POLICY.md`: polecenie
   użytkownika i bieżące pliki mają pierwszeństwo. Historia Git służy do
   odtworzenia kontekstu i kolejności, lecz sama nie może nadpisać aktualnego
   kontraktu ani stanowić zgody.
7. Runtime rozwiązuje tylko zmienne jawnie zadeklarowane przez `VARIABLE` lub
   `SECRET`; pozostałe wpisy `.env` nie są przekazywane do procesu potomnego.
8. Precedencja wartości wynosi: środowisko procesu, zadeklarowany `ENV_FILE`,
   wartość `DEFAULT`. Pusta wartość nie spełnia deklaracji `REQUIRED`.
9. `ENV_FILE` musi być ścieżką względną pozostającą w katalogu kontraktu.
   Interpolacja, wykonywanie poleceń i automatyczne rozwijanie `$NAME` w `.env`
   są zabronione.
10. Wartości `SECRET` istnieją tylko w pamięci procesu i muszą być redagowane
    w raportach oraz diagnostyce.

## ŚRODOWISKO RUNTIME DSL

```dsl
ENV_FILE ".env" OPTIONAL
VARIABLE DEFAULT_AGENT TYPE STRING FROM ENV DEFAULT "antigravity"

RULE C-ENV-001 TYPE REQUIRED
WHEN DECLARED_ENVIRONMENT_VARIABLE_USED
DO RESOLVE_ENVIRONMENT_WITH "python3 scripts/governance_env.py check"
DO REQUIRE ONLY_DECLARED_VARIABLES_EXPORTED
ASSERT SECRET_VALUES_REDACTED
NEXT ANALYSIS OR BLOCKED
```

Sprawdzenie kontraktu nie modyfikuje środowiska bieżącej powłoki:

```bash
python3 scripts/governance_env.py check
```

Polecenie wymagające zadeklarowanych wartości należy uruchomić bezpośrednio
przez runtime, bez `source .env` i bez `eval`:

```bash
python3 scripts/governance_env.py run -- command arg1 arg2
```

## STATE

```dsl
STATE START
STATE ANALYSIS
STATE BACKLOG
STATE PLAN
STATE WAIT_FOR_APPROVAL
STATE TOOLS
STATE DELEGATION
STATE EDIT
STATE VALIDATION
STATE PUBLICATION
STATE DONE
STATE BLOCKED

TRANSITION START -> ANALYSIS
TRANSITION ANALYSIS -> BACKLOG WHEN WORK_IS_DEFERRED
TRANSITION BACKLOG -> PLAN WHEN PLANNING_RESUMES
TRANSITION ANALYSIS -> PLAN
TRANSITION PLAN -> TOOLS WHEN USER_REQUEST_AUTHORIZES_EXECUTION_OR_AUTONOMOUS_MODE
TRANSITION PLAN -> WAIT_FOR_APPROVAL WHEN REQUIRED_EXECUTION_AUTHORITY_IS_MISSING
TRANSITION WAIT_FOR_APPROVAL -> PLAN WHEN MATERIAL_OBJECTIVE_EXPANSION
TRANSITION WAIT_FOR_APPROVAL -> TOOLS WHEN SESSION_EXECUTION_AUTHORIZATION_RECEIVED
TRANSITION TOOLS -> DELEGATION
TRANSITION DELEGATION -> EDIT
TRANSITION EDIT -> VALIDATION
TRANSITION VALIDATION -> PUBLICATION
TRANSITION PUBLICATION -> DONE WHEN TRUSTED_MERGE_IS_INTEGRATED_AND_GOVERNANCE_ONLY_CLOSURE_IS_RECORDED
TRANSITION ANY -> BLOCKED WHEN REQUIRED_EVIDENCE_MISSING
TRANSITION BLOCKED -> PLAN WHEN BLOCKER_RESOLVED_AND_SCOPE_REVIEW_REQUIRED
TRANSITION BLOCKED -> IN_PROGRESS WHEN BLOCKER_RESOLVED_AND_APPROVED_SCOPE_UNCHANGED
```

## PROCEDURA WAIT_FOR_APPROVAL

```dsl
RULE C-APPROVAL-001
```

## CHANGE EVALUATION

`change-evaluation.json` jest jednym kanonicznym widokiem oceny konkretnej
zmiany. Nie zastępuje intentu, governance gate ani dowodów `todo2code`; wiąże
je w raport przeznaczony do deterministycznej walidacji. Wynik obowiązuje
wyłącznie dla dokładnej krotki `baseSha + headSha + mergeBaseSha + intentHash
+ policyHash + manifestLockHash + approvalScopeHash`.

```text
zaakceptowana intencja + polityka + zaakceptowana baza
                         |
                         v
                  commit / push / PR
                         |
                         v
             dowody implementacji i walidacji
                         |
                         v
       twarde bramki + niezależne wymiary oceny
                         |
                         v
       change-evaluation.json + raport Markdown
                         |
                         v
          niezależne zatwierdzenie exact-head
                         |
                         v
                       merge
```

Twarde bramki są niekompensowalne. Wymiary pomagają reviewerowi, ale nie
mogą zamienić bramki `FAILED`, `UNKNOWN` lub `WAITING` na zgodę. Lokalny raport
nie jest trust rootem; zaufanie nadal powstaje wyłącznie w chronionym workflow,
review GitHub App/człowieka albo poprzez zweryfikowaną atestację.

```dsl
CHANGE_EVALUATION_SCHEMA = "t2c.change-evaluation/v1"
CHANGE_EVALUATION_RUNTIME = "bash scripts/runtime.sh"
PUBLICATION_MODE = PULL_REQUEST_REQUIRED_FOR_IMPLEMENTATION
DIRECT_PUSH = FORBIDDEN_FOR_IMPLEMENTATION

RULE C-EVALUATION-001 TYPE REQUIRED
WHEN COMMIT_CREATED OR PUSH_RECEIVED OR PULL_REQUEST_SYNCHRONIZED
DO RESOLVE BASE_SHA HEAD_SHA MERGE_BASE_SHA
DO HASH ACTIVE_TICKET_INTENT CURRENT_POLICY MANIFEST_LOCK
ASSERT EVALUATION_BOUND_TO_EXACT_CHANGESET

RULE C-EVALUATION-002 TYPE REQUIRED
WHEN IMPLEMENTATION_DIFF_EXISTS
DO REQUIRE EACH_CHANGED_PATH_AND_SYMBOL RESOLVES_TO_EXACTLY_ONE_ACTIVE_TICKET
DO REQUIRE IMPLEMENTATION_DIFF_IS_SUBSET_OF_ALLOWED_PATHS
FORBID MIX_UNRELATED_TICKET_SCOPES
ASSERT CHANGE_SCOPE_TRACEABLE

RULE C-EVALUATION-003 TYPE REQUIRED
WHEN ACTIVE_TICKET_HAS_ACCEPTANCE_CRITERIA
DO MAP EACH_REQUIRED_CRITERION_TO_IMPLEMENTATION_EVIDENCE
DO MAP EACH_REQUIRED_CRITERION_TO_VALIDATION_EVIDENCE
DO SET CRITERION_STATUS IN [SATISFIED, PARTIAL, FAILED, UNKNOWN, NOT_APPLICABLE]
FORBID SET SATISFIED_WITHOUT_REFERENCED_EVIDENCE
ASSERT CRITERION_COVERAGE_EXPLICIT

RULE C-EVALUATION-004 TYPE REQUIRED
WHEN REQUIRED_GATE IN [FAILED, UNKNOWN, WAITING]
DO SET MERGE_VERDICT = BLOCKED
FORBID COMPENSATE_REQUIRED_GATE_WITH_NUMERIC_SCORE
ASSERT HARD_GATES_HAVE_PRECEDENCE

RULE C-EVALUATION-005 TYPE REQUIRED
WHEN HEAD_SHA_OR_INTENT_HASH_OR_POLICY_HASH_OR_MANIFEST_LOCK_HASH_CHANGED
DO INVALIDATE PREVIOUS_EVALUATION
DO INVALIDATE PREVIOUS_APPROVAL WHEN APPROVAL_SCOPE_HASH_CHANGED
ASSERT REVIEW_APPLIES_TO_CURRENT_CHANGESET_ONLY

RULE C-EVALUATION-006 TYPE REQUIRED
WHEN PROJECT_DIRECTION_AFFECTED
DO COMPARE SEMANTIC_DELTA_WITH_ARCHITECTURE_INVARIANTS GOALS AND NON_GOALS
DO REPORT RESPONSIBILITY_MOVEMENT DEPENDENCY_DIRECTION API_CHANGE AND DUPLICATION
ASSERT DIRECTION_ASSESSMENT_REFERENCES_EXPLICIT_CONTRACT_OR_IS_LABELLED_INFERENCE

RULE C-EVALUATION-007 TYPE REQUIRED
WHEN LLM_ANALYSIS_PRODUCED
DO RECORD MODEL VERSION INPUT_DIGEST OUTPUT_DIGEST CONFIDENCE AND EVIDENCE_REFERENCES
FORBID LLM_OUTPUT_AS_TRUSTED_APPROVAL
FORBID LLM_ONLY_FINDING_BLOCK_MERGE_UNLESS_CONFIRMED_BY_POLICY_OR_HUMAN
ASSERT LLM_CONCLUSIONS_REMAIN_ADVISORY_OR_VERIFIED

RULE C-EVALUATION-008 TYPE REQUIRED
WHEN PARTICIPANT_CONTRIBUTION_CLAIMED
DO REQUIRE CLAIM_TO_REFERENCE COMMIT SYMBOL TEST REVIEW_FINDING DECISION OR EVIDENCE
FORBID USE_LINE_COUNT_OR_COMMIT_COUNT_AS_SOLE_VALUE_MEASURE
ASSERT CONTRIBUTION_TRACEABLE_TO_ACCEPTED_OUTCOME

RULE C-EVALUATION-009 TYPE REQUIRED
WHEN PULL_REQUEST_ENTERS_MERGE_GROUP
DO REEVALUATE_AGAINST_CURRENT_TARGET_HEAD
DO VERIFY CROSS_TICKET_DEPENDENCIES CONFLICTS AND INTEGRATION_WORKSTREAM
ASSERT MERGED_RESULT_PRESERVES_ACCEPTED_INTENT

RULE C-EVALUATION-010 TYPE REQUIRED
WHEN CHANGE_EVALUATION_COMPLETED
DO GENERATE MACHINE_REPORT AND HUMAN_REPORT
DO SIGN_OR_ATTEST REPORT_DIGEST
DO PUBLISH REQUIRED_STATUS_CHECK "todo2code/change-evaluation"
ASSERT REPORT_PROVENANCE_VERIFIABLE
```

Minimalne uruchomienie walidatora:

```bash
bash scripts/runtime.sh policy --policy CONTRIBUTING.md
bash scripts/runtime.sh validate \
  --evaluation change-evaluation.json \
  --intent project/ticket-014/intent.json \
  --manifest-lock .governance/manifest.lock.json \
  --repository-root . \
  --json-out change-evaluation.validated.json \
  --markdown-out change-evaluation.md
```

Runtime wykonuje zamknięty zestaw deterministycznych kontroli. Nie wykonuje
tekstu DSL, nie uruchamia LLM i nie uznaje lokalnego pliku za zaufane
zatwierdzenie. Producentem pełnych dowodów semantycznych może być `todo2code`;
chroniony workflow lub Validator App odpowiada za zewnętrzne pochodzenie,
podpis/atestację i publikację required status check.

## KANONICZNY ZAPIS BŁĘDÓW I ROZWIĄZAŃ

Rozwiązanie sytuacji operacyjnej ma trzy warstwy, z których żadna nie zastępuje
pozostałych:

1. `POLICY.md` lub `CONTRIBUTING.md` definiuje normatywną regułę i zakazy.
2. `governance/diagnostics.json` rejestruje stabilny kod, ogólny komunikat i
   najkrótszą bezpieczną remediację. Jest to maszynowe źródło nawigacji.
3. `error/*.md` opisuje procedurę człowieka/agenta, gdy rozwiązanie ma wiele
   kroków, wymaga klasyfikacji danych albo zawiera ryzyko destrukcji.

Finding validatora może zawierać bardziej szczegółowy komunikat, ścieżki,
evidence i remediację dla konkretnego uruchomienia. Ticket zapisuje pochodzenie,
decyzję i dowody zmiany standardu; nie jest kanonicznym runbookiem dla kolejnych
incydentów.

```dsl
RULE C-DIAGNOSTIC-001 TYPE REQUIRED
WHEN RUNTIME_EMITS_STABLE_GOV_CODE
DO REQUIRE CODE_IN "governance/diagnostics.json"
DO REQUIRE NONEMPTY_CANONICAL_MESSAGE_AND_REMEDIATION
ASSERT EMITTED_AND_REGISTERED_CODE_SETS_ARE_EQUAL

RULE C-DIAGNOSTIC-002 TYPE REQUIRED
WHEN DIAGNOSTIC_DOCUMENTATION_LINK_EXISTS
DO REQUIRE RELATIVE_PATH_MATCHING "error/*.md"
DO REQUIRE SECTIONS [SITUATION, MEANING, SAFE_RESOLUTION, VERIFICATION, DO_NOT, RELATED_RULES]
FORBID BYPASS_DISABLE_FORCE_OR_DATA_DELETION_WITHOUT_CLASSIFICATION
ASSERT RUNBOOK_IS_ACTIONABLE_FAIL_CLOSED_AND_MACHINE_LINKED

RULE C-DIAGNOSTIC-003 TYPE REQUIRED
WHEN REUSABLE_SOLUTION_DISCOVERED_IN_TICKET_LOG_OR_INCIDENT
DO PROMOTE_STABLE_RULE_TO_POLICY_OR_PROCEDURE
DO REGISTER_STABLE_CODE_AND_REMEDIATION WHEN_DETERMINISTIC_FAILURE_EXISTS
DO CREATE_OR_UPDATE "error/*.md" WHEN_RESOLUTION_IS_MULTISTEP_OR_RISKY
FORBID LEAVE_ONLY_HISTORICAL_TICKET_EVIDENCE
ASSERT FUTURE_OPERATOR_CAN_RESOLVE_WITHOUT_READING_GIT_HISTORY

RULE C-REMEDIATION-001 TYPE REQUIRED
WHEN DIAGNOSTIC_FINDINGS_REQUIRE_MULTI_STEP_TARGET_REFACTOR
DO CREATE TARGET_OWNED "project/{TICKET_ID}/remediation-intent.dsl.json"
DO BIND REPORT_DIGEST TICKET REPOSITORY OUTCOME NON_GOALS SCOPE EVIDENCE
DO DECLARE APPLICABILITY_SIGNALS EXCLUDED_SIGNALS ACTION_DAG AND DETERMINISTIC_VERIFICATION
ASSERT EACH_ACTION_RESOLVES_FINDING_WITHIN_ALLOWED_PATHS

RULE C-REMEDIATION-002 TYPE REQUIRED
WHEN REMEDIATION_INTENT_IS_GIVEN_TO_LLM_OR_EXECUTION_AGENT
DO VALIDATE_WITH ".governance/remediation_intent.py validate"
DO BLOCK READY_INTENT_WITH_UNRESOLVED_PATH_OWNER_EVIDENCE_OR_AUTHORIZATION
FORBID LLM_INVENT_PATH_OWNER_EVIDENCE_AUTHORIZATION_OR_APPLICABILITY
ASSERT ACCEPTED_INTENT_REMAINS_THE_AUTHORITY_BOUNDARY

RULE C-REMEDIATION-003 TYPE REQUIRED
WHEN TODO2CODE_ANALYZES_REMEDIATION_INTENT
DO RENDER_CANONICAL_TASK_AND_TODO_FROM_ACCEPTED_INTENT
DO BIND TODO2CODE_DIAGNOSTICS_AND_PLANS_BY_SHA256
DO REPORT SCOPE_EXPANSION CRITERION_GAP PRIORITY_DRIFT AMBIGUITY CONFLICT_AND_UNAUTHORIZED_DELETION
DO ADD DIGEST_BOUND_LLM_HINTS WITH_AUTHORITY ADVISORY
ASSERT TODO2CODE_OR_LLM_OUTPUT_CANNOT_EXPAND_ACCEPTED_INTENT

RULE C-REMEDIATION-004 TYPE REQUIRED
WHEN REMEDIATION_KNOWLEDGE_IS_STORED
DO KEEP REUSABLE_DIAGNOSTIC_IN "governance/diagnostics.json"
DO KEEP REUSABLE_MULTISTEP_RUNBOOK_IN "error/*.md"
DO KEEP INCIDENT_SPECIFIC_INTENT_IN TARGET_REPOSITORY_TICKET
FORBID TARGET_REPORT_TICKET_LOG_OR_REMEDIATION_INTENT_IN_GOVERNANCE_HUB
ASSERT STORAGE_LOCATION_MATCHES_OWNERSHIP_AND_REUSE_LIFETIME

RULE C-REMEDIATION-005 TYPE REQUIRED
WHEN TODO2CODE_PROJECTION_OR_ANALYSIS_IS_USED
DO RENDER ONE_ATOMIC_ACTION_RECORD_PER_DSL_ACTION
DO WRITE_ATOMICALLY_TO DECLARED_TASK_AND_TODO_PATHS
DO VERIFY_BYTE_EXACT_PROJECTIONS_BEFORE_EXTRACTION
DO CORRELATE_GRAPH_RECORDS_BY DECLARED_PROJECTION_SOURCE_PATH
DO ANALYZE_ONLY_PLANS_AND_DIAGNOSTICS_CITING_CORRELATED_RECORDS
DO BIND GRAPH_DIAGNOSTICS_PLANS_AND_RECORD_IDS_IN_ADVISORY_OVERLAY
FORBID UNRELATED_REPOSITORY_HISTORY_EXPAND_OR_BLOCK_INCIDENT_INTENT
ASSERT PROJECTION_AND_ADVISORY_ANALYSIS_ARE_REPRODUCIBLE_AND_INTENT_SCOPED
```

## LOG DECYZJI AUTONOMICZNYCH (DECISION_LOG)

Każda decyzja agenta, która wpływa na stan repozytorium lub na zaufane
zatwierdzenie (approve / request changes / merge readiness), musi mieć
**przeliczalny** wpis. Log prozy LLM nie jest dowodem: strona trzecia odtwarza
werdykt z `INPUT` i `APPLIED_RULE` bez czytania `ADVISORY`.

Maszynowy kontrakt JSON: `governance/decision-record.schema.json`
(`new-project.decision-record/v1`). Forma DSL i JSON są wzajemnie wyprowadzalne
przez `scripts/decision_record.py`. Wpis powinien być **wyprowadzany** z
`t2c.change-evaluation/v1`, gdy ocena zmiany istnieje — nie pisany niezależnie.

```dsl
DOCUMENT DECISION_LOG
VERSION 1
LANGUAGE PL
MODE STRICT
PURPOSE "sprawdzalny zapis decyzji podejmowanych autonomicznie"
POLICY "POLICY.md"

RULE C-DECISION-001 TYPE REQUIRED
WHEN AGENT_DECISION_AFFECTS_REPOSITORY_STATE
DO APPEND DECISION_RECORD TO "project/{TICKET_ID}/decisions.md"
DO REQUIRE RECORD_BINDS (DECISION_ID AND TICKET AND HEAD_SHA AND CORRELATION_ID)
DO REQUIRE RECORD_NAMES APPLIED_RULE_ID
FORBID DECISION_WITHOUT_RECORD
ASSERT RECORD_IS_APPEND_ONLY
NEXT VALIDATION OR BLOCKED

RULE C-DECISION-002 TYPE REQUIRED
WHEN DECISION_RECORD_WRITTEN
DO REQUIRE DETERMINISTIC_INPUTS_STORED_VERBATIM
DO REQUIRE REJECTED_ALTERNATIVE_AND_ITS_BLOCKING_RULE
FORBID SUMMARY_IN_PLACE_OF_INPUTS
ASSERT VERDICT_RECOMPUTABLE_FROM_RECORD_ALONE
NEXT VALIDATION OR BLOCKED

RULE C-DECISION-003 TYPE FORBIDDEN
WHEN LLM_OUTPUT_PRESENT_IN_DECISION_RECORD
DO REQUIRE AUTHORITY_LABEL IN ["DETERMINISTIC", "ADVISORY"]
FORBID TREAT_ADVISORY_AS_VERDICT
ASSERT VERDICT_AUTHORITY = "DETERMINISTIC"
NEXT VALIDATION OR BLOCKED

RULE C-DECISION-004 TYPE REQUIRED
WHEN DECISION_RECORD_REVIEWED
DO REPLAY DETERMINISTIC_INPUTS_AGAINST_APPLIED_RULE
DO REQUIRE REPLAYED_VERDICT = RECORDED_VERDICT
FORBID ACCEPT_RECORD_THAT_CANNOT_BE_REPLAYED
ASSERT DIVERGENCE_REPORTED_WITH_STABLE_DIAGNOSTIC_CODE
NEXT PUBLICATION OR BLOCKED
```

Kształt wpisu (fence `dsl`):

```dsl
DECISION D-031-0007
TICKET ticket-031
HEAD_SHA 4116ae07a1c39f2b8d5e1c0a7b3f9d2e6c8a4b10
CORRELATION_ID new-project-pr-41-ticket-031-4116ae07a1
ACTOR agent:validator
APPLIED_RULE P-CORE-015
INPUT required_checks = ["test","windows-governance"]
INPUT observed_checks = ["test=PASS","windows-governance=PASS"]
VERDICT APPROVE AUTHORITY DETERMINISTIC
REJECTED REQUEST_CHANGES BECAUSE NO_UNSAFE_CHANGE_REASON_FOUND
ADVISORY llm_verdict = "APPROVE" MODEL "openrouter/z-ai/glm-5.2"
ASSERT VERDICT_AUTHORITY != "ADVISORY"
```

Kody: `GOV-DECISION-001` (brak logu / naruszenie append-only),
`GOV-DECISION-002` (wpis nieprzeliczalny), `GOV-DECISION-003` (ADVISORY jako
werdykt), `GOV-DECISION-004` (rozjazd przy odtworzeniu).

## PROCEDURA PUBLICATION

```dsl
RULE C-PUBLISH-001
WHEN USER_DID_NOT_REQUEST_COMMIT
DO SKIP COMMIT
DO SKIP PUSH
ASSERT GIT_HISTORY_UNCHANGED
NEXT DONE

RULE C-PUBLISH-002
WHEN USER_REQUESTS_COMMIT
DO REVIEW "git status --short"
DO REVIEW "git diff"
DO COMMIT_ATOMIC_CHANGE
ASSERT COMMIT_DESCRIBES_REASON
NEXT DONE

RULE C-PUBLISH-003
WHEN USER_REQUESTS_IMPLEMENTATION_PUBLICATION
DO PUSH_TICKET_BRANCH_ONLY_AFTER_COMMIT
DO OPEN_OR_UPDATE_PULL_REQUEST_BOUND_TO_EXACTLY_ONE_TICKET
DO KEEP TICKET_STATUS = IN_PROGRESS AND WORKFLOW_STATE = PUBLICATION UNTIL TRUSTED_MERGE_INTEGRATES_HEAD
FORBID DIRECT_PUSH_TO_DEFAULT_BRANCH
ASSERT PUBLICATION_MODE = PULL_REQUEST_REQUIRED_FOR_IMPLEMENTATION
ASSERT UNMERGED_IMPLEMENTATION_HEAD_RETAINS_ACTIVE_TICKET_AUTHORITY
NEXT PUBLICATION OR BLOCKED

RULE C-PUBLISH-004
WHEN DIRECT_PUSH_EXCEPTION_REQUESTED
DO REQUIRE CLASSIFICATION IN [docs-only, generated-artifact, emergency-with-signed-attestation]
DO REQUIRE EVIDENCE_AT_LEAST_AS_STRONG_AS_PULL_REQUEST_FLOW
FORBID USE_EXCEPTION_AS_PROCESS_BYPASS
ASSERT EXCEPTION_IS_EXPLICIT_SCOPED_AND_AUDITABLE
NEXT DONE

RULE C-PUBLISH-005
WHEN GOVERNED_GOAL_DELIVERY_ENABLED
DO REQUIRE "goal.yaml" GOVERNANCE_DELIVERY require_goal_a = true
DO REQUIRE GOAL_FEATURE_PROBE SUPPORTS "--delivery-mode" AND [direct-main, publish-only, pull-request]
DO REQUIRE REQUESTED_DELIVERY_MODE IN GOVERNANCE_DELIVERY_ALLOWED_MODES
FORBID ACCEPT_GOAL_VERSION_NUMBER_AS_SOLE_CAPABILITY_EVIDENCE
ASSERT GOAL_DELIVERY_POLICY_AND_RUNTIME_CAPABILITY_VERIFIED_BEFORE_SIDE_EFFECTS
NEXT PUBLICATION OR BLOCKED

RULE C-PUBLISH-006
WHEN USER_REQUESTS_IMPLEMENTATION_PUBLICATION AND GOVERNED_GOAL_DELIVERY_ENABLED
DO RUN "goal --delivery-mode pull-request --no-publish -a push --ticket {TICKET_ID}"
DO REQUIRE PULL_REQUEST_BOUND_TO_EXACTLY_ONE_TICKET_AND_CURRENT_HEAD
FORBID RAW_GIT_PUSH DIRECT_MAIN PUBLISH_ONLY REGISTRY_PUBLISH TAG_OR_RELEASE_CREATION
ASSERT IMPLEMENTATION_PUBLICATION_STOPS_AT_REVIEWABLE_PULL_REQUEST
NEXT PUBLICATION OR BLOCKED

RULE C-PUBLISH-007
WHEN TRUSTED_MERGE_IS_READY_FOR_REGISTRY_OR_IMMUTABLE_RELEASE AND GOVERNED_GOAL_DELIVERY_ENABLED
```
